Calling a personal repo's reusable workflow (jflowers/ship pr-scope.yml) as a repo's merge-gate scope detector creates a chicken-and-egg recovery failure mode: when the dependency becomes unresolvable (deleted, privatized, renamed, or pinned commit unreachable), scope fails closed on every PR (correct direction), but repinning the SHA requires merging a PR through the very gate the broken pin fails — the only exits are an admin merge bypassing branch protection or an emergency org safe-settings edit. Unlike inlining the detector in-repo (as replicator and gaze did for the same skip-heavy-jobs pattern), reusable-call gating must ship with a documented break-glass/repin runbook at the `uses:` line (symptom: CI OK red with "::error::scope: failure"; repin procedure per CI-002: resolve source main or tag, derive SHA from the API, never from memory; escape hatch: verify whether branch protection includes administrators before the outage, not during it).
